# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AppservR is a Go server that deploys and reverse-proxies R Shiny applications. It launches one or more `Rscript` subprocesses per configured app (via `shiny::runApp`), load-balances user sessions across those instances, and serves an admin web UI to manage apps/users/groups — all as a single dependency-free binary (only a local R installation is required). It targets Linux and Windows.

## Common commands

```sh
go mod tidy                # sync dependencies
go generate ./...          # regenerate embedded assets/templates (vfsgen) and wire DI code — run after
                            # changing files under assets/, templates/, or wire.go
go build .                 # build the appservR binary
go test ./...              # run all tests
go test ./models/...       # run tests for a single package
go test ./models/... -run TestDataModelDB/user=lifecycle   # run a single (sub)test
```

CI (`.github/workflows/run-tests.yml`) runs on Linux and Windows and simply does `go mod tidy && go generate ./... && go test ./...`. There is no lint step configured.

Releases are built with GoReleaser (`.goreleaser.yml`), cross-compiling for windows/386, windows/amd64, and linux/amd64 with `CGO_ENABLED=1` (needs mingw toolchains for Windows cross-compilation, and `go generate ./...` / `go mod tidy` run as pre-hooks).

Running locally:
```sh
go run . serve -a localhost -p 8080 -m debug   # serve directly
go run . service install|start|stop|remove     # manage as an OS service (kardianos/service)
```
On first run, `config.yml` is written next to the executable and a default SQLite DB + sample Shiny app are created.

## Code generation and dependency injection

- **Wire (`wire.go` / `wire_gen.go`)**: `InitializeServer` is generated by [google/wire](https://github.com/google/wire). `wire.go` (build tag `wireinject`) declares the provider set; `wire_gen.go` is the generated, compiled version — **do not hand-edit `wire_gen.go`**, change `wire.go` and regenerate instead (`go run github.com/google/wire/cmd/wire`, invoked implicitly by `go generate ./...` per the `//go:generate` directive in `wire_gen.go`).
- **vfsgen (`modules/vfsdata/`)**: `generate_assets.go` (build tag `ignore`) embeds `assets/` and `templates/` into Go source (`modules/vfsdata/assets/vfsdata.go`, `modules/vfsdata/templates/vfsdata.go`) so the binary has no external file dependencies at runtime. `modules/vfsdata/fs.go` decides, based on `mode` (prod vs debug), whether to serve from the embedded FS or straight from disk — so in debug mode you can edit templates/assets without regenerating.
- `build_tools.go` (build tag `tools`) just pins the `wire` and `vfsgen` tool versions in `go.mod`.

## Architecture

**Request flow**: `main.go` (cobra CLI + `kardianos/service` wrapper for OS service install/start/stop) → `InitializeServer` (wire-built) → `server.NewAppRouter` (gin engine) → per-request middleware chain → `appserver.AppServer.CreateProxy()` reverse-proxies to the right Shiny process.

**`server/` (gin routing)**:
- `router.go` builds the gin engine, loads HTML templates (embedded or on-disk, see above), mounts `/assets`, then in order: global `middlewares.Auth()` (parses JWT cookie, sets `username`/`displayedname`/`groups` in context if present) → `/auth` routes (login/signup, unauthenticated) → `/admin` routes (behind `middlewares.AdminAuth()`, requires `groups["admins"]`) → catch-all `appServer.CreateProxy()` for everything else (the actual Shiny app traffic).
- `adminroutes.go` / `authroutes.go` wire URLs to `controllers/*`.

**`modules/appserver/` — the core of the app**:
- `AppServer` (`appserver.go`) holds all configured apps in two indexes: `appsByName` (map) and `byPath` (slice sorted so longer/more-specific paths are matched before shorter prefixes — see `prefixSort`, needed because apps can be nested like `/` and `/myapp` and `/myapp/private`).
- `AppProxy` (`app.go`) represents one configured app: its DB settings (`models.App`), its `AppSource`, its live `Instances` (Rscript subprocesses) and `Sessions` (user sessions), and a periodic session-GC timer (30 min inactivity). `Rescale()` starts/stops `Instance`s to match `App.Workers` (or 0 if the app is inactive); when scaling down it phases out the least-used instances first so in-flight users aren't dropped.
- `Instance` (`instance.go`, plus `instance_linux.go`/`instance_windows.go` for OS-specific process-group kill/signal handling) wraps one `Rscript -e "shiny::runApp(...)"` subprocess: it gets a free port from `modules/portspool`, watches stdout/stderr for the `"Listening on"` line to flip status to RUNNING, auto-restarts on unexpected exit with exponential backoff, and tracks a live `userCount`.
- `Session` (`session.go`) binds a browser session (cookie `appservr_session`) to a specific `Instance`, so a user keeps hitting the same R process across requests (Shiny apps are stateful per-process).
- `proxy.go`'s `CreateProxy()` gin handler: matches request path to an `AppProxy` (`GetApp`, using `byPath`), enforces `AppProxy.Authorized()` (public / all logged-in users / specific groups, from `models.App.RestrictAccess` + `AllowedGroups`), finds-or-creates a `Session`, rewrites the request to `http://localhost:<instance port>` (stripping the app's path prefix) via `httputil.ReverseProxy`, sets `appservr_appid`/`appservr_session` cookies, and forwards `appservR-username`/`appservR-displayedname`/`appservR-appname` headers to the Shiny process. Handles WebSocket upgrades (Shiny's reactive protocol) and closes the session when the socket disconnects.
- `modules/portspool`: simple mutex-guarded allocator handing out free TCP ports starting at 4000 for new instances.
- `modules/appsource`: abstracts where an app's R source comes from — currently `AppSourceDir` (a local directory, validated to contain `app.R` or `server.R`+`ui.R`) and `sampleapp.go` (writes a bundled demo Shiny app to `<exeFolder>/apps/sample-app` on first run). `AppSource` is an interface, so a git-based source (there are `GitSourceUrl`/`GitSourceBranch`/`GitSourceToken` fields already on `models.App`) is the natural extension point, though only the directory/sample-app implementations exist today.

**`models/`** — GORM (SQLite by default) models for `App`, `User`, `Group`, each exposed through a `*Model` interface (`AppModel`, `UserModel`, `GroupModel`) with a `*ModelDB` implementation, wired in via `wire.Bind`. Each `*ModelDB` also exposes `AsMap`/`AsMapSlice` to flatten records (e.g. turning `AllowedGroups []Group` into a `map[string]bool`) for direct use in HTML templates. `db.go`'s `NewDB` auto-migrates all three models on startup.

**`modules/config`**: `Config` interface backed by `ConfigViper` (spf13/viper). Reads/writes `config.yml` next to the executable (or `/etc/appname`, `$HOME/.appname`), with defaults for server host/port, `Rscript` path (auto-detected on Windows by scanning `C:/Program Files/R`), and SQLite path. Also owns log level (`WARNING` in prod mode, `DEBUG` otherwise) and defines the `AccessLevels` enum (`PUBLIC`/`ALL_USERS`/`SPECIFIC_GROUPS`) used by app access control.

**`modules/auth`**: stateless JWT auth. `GenerateToken`/`ValidateToken` sign/verify HS256 tokens (15 min expiry) carrying username, displayed name, and a comma-joined group list. Signing secret is `APPSERVR_AUTH_SECRET` env var if set, otherwise a random UUID generated at process start (meaning tokens don't survive a restart unless that env var is set).

**`modules/ssehandler`**: a `MessageBroker` broadcasting Server-Sent Events (used to live-update the admin apps list, e.g. connected-user counts, without polling) — see `admin.GET("/apps.json", msgBroker.Controller())`.

**`controllers/`**: gin handlers for apps/users/groups/auth admin CRUD, sitting between `server/` routes and `models/`+`appserver`.

## Testing notes

`models/models_test.go` is the only test file; it uses an in-memory SQLite DB (`database.path: "memory"`) and a hand-rolled `MockConfig` implementing the `config.Config` interface — follow that pattern (in-memory DB + mock config) for new model-layer tests rather than hitting a real file-backed DB.
